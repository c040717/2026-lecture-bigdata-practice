# 5주차 관찰 기록

## Task 1
고장 버전에서는 dead end에 도착한 점수를 다음 반복으로 넘기지 않아 총합이 0이 됐다. 정상 버전은 이 점수를 모든 노드에 고르게 나누어 총합 1을 유지했다.
spider trap의 C와 D는 고장 버전에서 전체 점수를 차지했다. 재분배와 순간이동으로 이동 경로를 전체 페이지에 연결하니 trap 밖 A와 B에도 각각 0.0375와 약 0.0694의 점수가 남았다.
β는 링크를 따라갈 확률이고 1-β는 임의의 페이지로 순간이동할 확률이다. 순간이동 덕분에 연결이 적거나 trap 밖에 있는 페이지에도 도달할 수 있다.

## Task 2
노드 1,200개에서 β를 0.5→0.99로 높이니 수렴에 필요한 반복이 14→24회로 늘었다. 순간이동이 줄어 이전 분포의 영향이 오래 남기 때문이며, β=0.85에서 tol을 1e-3→1e-10으로 줄이면 7→20회로 한 자리당 평균 약 1.86회가 더 필요했다.
노드 수가 1,200→12,000으로 10배 늘어도 β=0.85의 반복은 20→21회였다. 시간은 0.0227403→0.2374761초로 약 10.44배 늘었는데, 반복 횟수와 달리 매 반복의 계산량은 처리할 노드·간선 수에 따라 커지기 때문이다.
두 크기 모두 top-10의 구성은 같았지만 측정한 β 중 0.7에서 처음 p00000과 p00004의 7·8위가 바뀌었다. 상위 후보는 같아도 세부 순서는 달라질 수 있으므로 공개된 순위를 볼 때 β 선택도 확인해야 한다.

## Task 3
전이행렬 대신 기존 인접 리스트와 점수 사전 2개를 사용했다. 간선 정보는 O(n+m) 입력을 그대로 쓰고 추가 float는 임시값까지 2n+12를 상한으로 잡아, n=1,200에서 2,412개로 기준의 1,440,000개보다 약 597.0배 적었다.
순간이동과 dead end 재분배는 모든 노드에 같은 값 (1-β+β·dangling)/n을 더하므로 공통값 하나와 O(n) 초기화로 처리한다. 실제 간선을 따라 전달되는 점수만 O(m)으로 더하면 되어 n×n 행렬을 만들 필요가 없다.
이번 bench.py 측정에서는 약 71.1배 빨랐고 노드별 최대 차이는 1.17e-15로 1e-9 기준을 만족했다. 작은 차이는 부동소수점 덧셈·곱셈 순서가 달라 생긴 반올림 오차이며, float 개수의 배율은 실제 프로세스 RAM 사용량의 배율과는 다르다.
