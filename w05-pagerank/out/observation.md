# 5주차 관찰 기록

## Task 1
고장 버전은 dead end의 rank를 다음 노드로 보내지 않아 총합이 0이 됐고 spider trap의 C+D는 전체 rank를 차지했다. 정상 버전에서는 dead end의 rank를 모든 노드에 균등하게 재분배해 총합 1을 유지했다.
재분배는 dead end에서 확률질량이 사라지는 것을 막고 순간이동은 trap 밖에도 rank가 도달하게 한다. 두 경우 모두 특정 페이지에 갇힌 이동을 전체 노드로 다시 연결하는 방식이다.
β는 링크를 따라갈 확률이고 1-β는 임의의 노드로 순간이동할 확률이다. β=0.85에서 trap 밖 A와 B의 rank도 각각 0.0375와 약 0.0694로 남았다.

## Task 2
1,200개 노드에서 β를 0.5→0.99로 높이자 수렴 횟수가 14→24회로 늘었다. 순간이동이 줄면 기존 분포의 영향도 오래 남는다. β=0.85에서는 tol을 1e-3→1e-10으로 줄일 때 7→20회, 한 자리당 평균 약 1.86회가 더 필요했다.
노드 수가 1,200→20,000으로 약 16.67배가 돼도 β=0.85의 반복은 20→21회였지만 시간은 0.017466→0.400006초로 늘었다. 반복 횟수는 수렴 속도에, 각 반복의 시간은 처리할 노드·간선 수에 좌우되므로 두 증가율이 달랐다.
두 크기 모두 top-10 구성은 같았다. 측정한 값 중에서는 β=0.7에서 처음 p00000과 p00004의 7·8위가 바뀌었다. 상위 후보가 같아도 세부 순서는 달라질 수 있어 공개된 순위를 읽을 때 β도 확인해야 한다.

## Task 3
전이행렬 대신 기존 인접 리스트와 rank 벡터 2개를 사용했다. 간선은 기존 O(n+m) 구조를 재사용하고 추가 float 저장은 2n+8을 보수적 상한으로 잡았다. n=1,200에서는 2,408개로 기준의 1,440,000개보다 약 598배 적었다. 이 비율은 실제 프로세스 RAM 비율이 아니다.
순간이동과 dead-end 재분배는 모든 노드에 같은 값 `(1-β+β·dangling_mass)/n`을 더하므로 스칼라 하나와 O(n) 초기화로 처리된다. 간선의 기여만 O(m)으로 더하면 되어 n×n 행렬이 필요 없다.
수정하지 않은 bench.py의 이번 측정에서 약 71.6배 빨랐고 노드별 최대 차이는 1.17e-15로 1e-9 기준을 만족했다. 작은 차이는 밀집 방식과 희소 방식의 덧셈·곱셈 순서에 따른 부동소수점 반올림 때문이다.
