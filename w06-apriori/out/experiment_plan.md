# 6주차 실험 계획

- 제공된 생성기와 seed 246을 사용한다. 기본 데이터는 항목 2,000개, 바구니 20,000개, 평균 길이 설정 20이다. `bench.py`와 `PlainApriori`는 바꾸지 않는다.
- support를 400, 200, 100, 50, 25, 12, 6, 3, 1 순서로 낮춘다. 후보 쌍 카운터, 빈발 쌍 수, 시간, 추가 할당 메모리를 기록한다. 각 조건이 끝날 때 바로 저장한다.
- 예상: 낮은 임계값에서는 살아남는 항목과 후보 쌍이 늘지만, 모든 항목이 살아남은 뒤에는 후보 카운터가 포화될 수 있다. 바구니 생성 시간은 측정에서 제외하고, tracemalloc을 켠 실행 시간임을 표시한다.
- 기본 데이터에서 한계에 도달하지 않으면 항목 10,000개, 바구니 40,000개, 평균 길이 설정 40으로 확장해 별도 기록한다. 확장 실험은 조건당 알고리즘 실행 30초 또는 프로세스 작업 집합 1 GiB 중 먼저 도달한 기준에서 중단한다. 중단된 조건의 최종 답 개수는 추정하지 않는다.
- PCY는 버킷 수를 바꾸어 같은 정답을 내는지 비교한다. 버킷 배열과 비트맵 크기를 따로 적고, 데이터 크기를 바꾼 추가 메모리 측정으로 실제 이득이 시작되는 구간을 찾는다.
- CPU와 설치 RAM은 실행 시 읽는다. Whale 브라우저, 대화형 데스크톱 프로그램, Windows Defender와 일반 Windows 백그라운드 작업이 실행 중인 상태에서 순차 측정한다.
