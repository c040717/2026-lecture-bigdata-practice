# 6주차 관찰 기록

## Task 1
제공된 7개 바구니에서 support를 2로 두면 cola→milk의 confidence는 1.0, milk→cola는 0.4였다. cola를 산 경우 milk도 샀다는 방향이 더 유용하지만, cola가 나온 바구니는 2개뿐이다.
이 조건에서 cola→milk는 최고 confidence 규칙 중 하나이고 lift는 1.4였다. milk의 기저율 5/7보다 높지만 표본이 작아 일반적인 구매 관계라고 단정하기는 어렵다.
항목 2,000개의 모든 쌍은 1,999,000개다. 기본 데이터의 support 50에서는 1패스를 통과한 항목 1,849개로 가능한 쌍이 1,708,476개가 되고, 실제 관측되어 카운터를 만든 쌍은 820,259개였다.

## Task 2
기본 데이터는 support 1까지 완료됐고, 확장 데이터에서 support 50을 실행하다 working set 1 GiB 기준에 먼저 도달해 중단했다. 감시 경과 시간은 19.93초였으며 컴퓨터 전체 RAM 부족이나 OOM은 아니었다.
기본 데이터의 support를 400→200→100→50으로 낮추자 카운터는 5.54→4.67→3.00배씩 늘었다. 25부터는 모든 항목이 살아남아 893,456개로 고정됐고, 반환할 정답이 늘면서 추가 메모리는 계속 증가했다.
support 50에서는 카운터 820,259개에 정답이 6,397개여서 약 128.2배 차이가 났다. 최종 빈도를 알기 전까지 드문 후보도 세어야 하기 때문이며, support 1에서는 관측된 모든 쌍이 정답이 되어 차이가 없어졌다.

## Task 3
버킷 1,048,576개로 정수 배열 비용을 4 MiB에 두면서 충돌을 줄였다. 기본 데이터에서 쌍 카운터는 820,259→13,017개로 98.4% 줄었고, 정답 6,397개와 각 빈도는 같았다.
비트맵은 0.125 MiB이고 변환 중에는 배열과 합쳐 본체만 4.125 MiB다. 객체 비용까지 추적한 추가 메모리는 102.29→4.68 MB였으며, support 50을 고정한 크기 비교에서 교차점은 바구니 4,000~8,000개 사이였다.
버킷을 65,536개로 줄이자 충돌 때문에 카운터 300,587개, 추가 메모리 27.62 MB로 늘었다. 4,096개에서는 모든 버킷이 빈발해 카운터가 baseline과 같은 820,259개가 됐으므로 배열만 줄이는 것이 해결책은 아니었다.
